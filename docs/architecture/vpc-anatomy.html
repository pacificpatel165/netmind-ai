Anatomy of a VPC

The four AWS networking primitives behind cloud/aws-networking/*.tf (BACKLOG.md item 29), and how they layer on top of each other: a VPC's address space, subnets carved out of it, route tables that decide what can reach the internet, and security groups that filter traffic independently of all of it.

Provisioned by: Terraform Simulated against: LocalStack's free tier Backs: BACKLOG.md item 29

1 — Routing: who can reach the internet

Public and private aren't labels you set on a subnet — they're a consequence of which route table it's attached to.

2 — Security groups: filtering by identity, not address

A separate, independent layer — it doesn't care which subnet something is in, only what's actually asking.

How the two layers combine

Routing and security groups are independent and additive, not redundant — traffic has to clear both to actually arrive. The route table gets a packet to the right subnet's network interface at all; the security group then decides, port by port and source by source, whether that interface accepts it. A resource in the private subnet is unreachable from the internet for a routing reason (no path out or in exists at all). A resource in the public subnet behind web-sg is still only reachable on 80, 443, and 22 from admin — reachable at the network layer, restricted at the security layer. Two different jobs, stacked.

The nearest thing in NETCONF/YANG terms: a route table is the literal routing table on an interface or VRF; a security group is closer to a stateful ACL/firewall policy object attached to that interface — except AWS's security groups support group-to-group references natively, which most on-prem ACL tooling has to fake with address sets kept manually in sync.

Terminology quick reference

Every abbreviation used above, spelled out in full, in the same order it first appears.

TermWhat it is
VPC
Virtual Private Cloud		An isolated, software-defined address space — the top-level container everything else lives inside. "Virtual" because it's not a physical network, just AWS's logical boundary; "Private" because nothing outside it can see in unless explicitly connected.
CIDR
Classless Inter-Domain Routing		The notation for writing an address range as one compact value, e.g. 10.60.0.0/16 — the part before the slash is the network's starting address, the number after the slash (the "prefix length") says how many of the address's leading bits are fixed. A smaller number after the slash means more addresses are covered: /16 covers 65,536 addresses, /24 covers 256. Every VPC and every subnet is sized with a CIDR block.
IP address
Internet Protocol address		The numeric address (e.g. 10.60.1.5) identifying one device on a network — what a CIDR block is a range of.
Subnet
sub-network		A smaller slice carved out of the VPC's CIDR block, pinned to one Availability Zone. Public vs. private is not a subnet attribute — it's whatever its attached route table allows (see below).
AZ
Availability Zone		A physically distinct AWS datacenter (or cluster of them) within a region, with its own power and networking, isolated so one AZ failing doesn't take down another. A subnet lives in exactly one AZ.
Route tableThe forwarding rules for a subnet's traffic — the same concept as a routing table on a router interface in traditional networking. One route table per subnet (a table can be shared across several subnets, though this exercise gives each its own).
IGW
Internet Gateway		AWS's managed, redundant edge device that hands traffic off to the real internet. Attached once per VPC; route tables point at it by its resource ID (an igw-... string) to send traffic there.
NAT Gateway
Network Address Translation Gateway		Would let a private subnet reach outbound internet (e.g. to download updates) without being reachable inbound — it rewrites ("translates") the private subnet's internal addresses to a public one for outgoing traffic only. Not provisioned in this exercise — LocalStack's current free tier doesn't emulate real ones.
SG
Security Group		A stateful, instance-level virtual firewall. Filters by port, protocol, and source — a source can be a CIDR block (an address range) or another security group's ID (a group of instances, by identity).
StatefulAllowing inbound traffic on a security group automatically permits the matching return traffic back out, without a separate rule for it — unlike a "stateless" Network ACL (Access Control List, a different, subnet-level filter not used in this exercise), which requires both directions to be opened by hand.
TCP
Transmission Control Protocol		The connection-oriented transport protocol behind the port numbers referenced throughout (22 for SSH, 80/443 for web traffic, 5432 for PostgreSQL) — what a security group's port rules are actually filtering.
